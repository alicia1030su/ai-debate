# AI Debate v0.2.1

生产可靠性增强。功能入口与页面布局与 v0.2.0 一致；变化集中在「长期跑着会不会出错」。

## 升级

覆盖程序即可。数据目录（默认 `%LOCALAPPDATA%\ai-debate` / `/var/lib/ai-debate`）无需任何手工操作：

- `monitors.json` 与 `auto-tasks.json` 会在首次启动时补齐新字段并写回（审计事件 `store.migrated`）。
- 旧监控目标保留名称、间隔、计数与游标；新增的 `compensationHours` 取默认 24 小时。
- 旧任务的 `needs_review` 状态保持原样；旧候选、旧批准、旧会话不被改写。
- 已用真实 v0.2.0 数据目录验证，详见 `docs/acceptance-v0.2.1.md`。

## 修了什么

### 存储：不再「报告成功但没写下去」

- 写完再改内存。磁盘满、权限错误、短写都会让本次操作失败并返回可读原因，不会出现「控制台显示已保存、重启后消失」。
- 写入后 `fsync` 目录项，断电不会留下「文件名指向空内容」。
- 损坏的 `monitors.json` / `auto-tasks.json` 先另存为 `.corrupt-<时间>`，再从 `.bak` 恢复；恢复会写审计。

### 监控：旧回复被改了也能发现

- 新增补偿扫描：默认每 6 小时回看最近 24 小时（可配 1–168 小时），按内容指纹识别编辑与删除。
- 手动「补偿扫描」和「全量重查」在监控行上直接可点。
- 游标只在扫描完整且新回复已落盘时前进；不完整会写明原因并留到下一轮重读。

### 任务：崩溃后可解释，不静默重放

- 记录每次模型调用的开始/结束；跨崩溃的调用标记为「结果不确定」，恢复记录里单独计数。
- 生成任务的去重键从「会话 + 回复」改为「监控 + 回复」——换一次分析不会再给同一条回复生成第二个候选。
- 修复长期挂机的关键缺陷：复用分析会话时会刷新评论上下文。此前第二条之后的新回复都会因「不在读取到的评论里」而无法生成候选。
- 队列新增：容量上限、历史保留（待审核永不删除）、卡死回收、手动重试、手动取消、积压告警。

### 状态中心

「自动挂机」页新增运行状态区：调度心跳、最后一次调度与耗时、最后一次成功读取、队列占用与最久等待、内存与常驻内存、数据目录占用、磁盘余量、最近一次崩溃恢复。

### Windows

- 新增 `--no-browser`：自启项使用它，登录时不会弹浏览器。
- 守护模式在服务被强杀后按 1s→30s 退避拉起；`stop` 是干净退出，守护不会对抗。

### Linux

- 安装包内新增 `logrotate` 配置（每周、保留 4 份、`copytruncate`）。
- 安装前检查磁盘余量（不足 200 MB 直接中止，不写任何文件）。
- 验收脚本增加独立用户与数据目录权限检查。

## 没变的部分

- 11 个配置页签、字段、按钮、审批流程。
- 后台仍然**不能发表**：候选终态是「待人工审核」，发表必须由人在审批页确认。
- 安全边界：未登录 401、跨站 403、SSRF 入口拦截、凭据加密且不回显、审计事件落盘。

## 已知限制

见 `docs/known-issues.md`。与本次最相关的三条：

1. 真实贴吧/微博账号的长期轮询仍未验证（无可用实号凭据）；一次匿名只读检查被平台拒绝/返回空页，已如实记录。
2. 24 小时墙钟压力测试未跑满；CI 跑 5 分钟、本机跑 2 分钟，测的是堆增长、候选唯一性与台账上限。
3. Debian 12 只验证了安装与二进制兼容性，未验证 systemd 生命周期（容器无 init）。

## 校验

同一 Release 附带 `SHA256SUMS.txt`：

```bash
sha256sum -c SHA256SUMS.txt          # Linux
certutil -hashfile AI-Debate-windows-x64.exe SHA256   # Windows
```
