# 已知问题（v0.1.0）

按影响排序。每条都写明「现在是什么行为」，不写「可能会」。

## 1. Windows 可执行文件未代码签名

首次运行可能被 SmartScreen 或第三方杀毒软件提示「未知发布者」。核对 Release 页的 SHA256 后自行决定放行。没有做签名是因为 v0.1.0 没有代码签名证书，伪造一个签名更糟。

## 2. Linux 只发布 x64

ARM64 需要单独构建（SEA 的注入目标必须是运行平台的 node 二进制）。v0.1.0 未提供，按需求「不以未完成 ARM64 阻断首版」处理。

## 3. 没有内置 TLS

`--host 0.0.0.0` 可以直接用，但口令会走明文 HTTP。远程访问必须自行加 Nginx/Caddy 反代，`docs/security.md` 说明了反代必须保留 `Host`/`Origin` 的原因。

## 4. 真实发表能力未在本环境实测

贴吧的真实发表需要有效 Cookie 与真实账号，v0.1.0 的验收在离线导入链路上完成（导入 → 分析 → 生成 → 编辑 → 批准 → 复制）。发表路径的代码与门禁未改动，但**没有在真实平台发出过一条回复**。未验证的平台能力在界面上保持「不可用」，不会出现可点的发表按钮。

## 5. 微博平台依赖外部 CLI

原插件通过官方 CLI 读取微博，独立版没有打包这个 CLI。因此微博路径在没有安装该 CLI 的机器上会显示「不可用」，而不是假装可用。贴吧的 HTTP 读取不受影响。

## 6. Agent 工具没有调用入口

9 个 `debate_*` 工具仍被注册到内存中的工具表，但独立版没有 agent。将来接 MCP 时可直接复用。当前它们的存在只体现在系统页的计数上。

## 7. 单管理员、无多用户

只有一个管理员账号，没有角色与权限分级。多人共用一台机器时，所有人都拥有全部权限。

## 8. 密码重置需要手动操作

忘记密码时：停服务 → 删除 `admin.json` → 重启 → 重新初始化。没有「邮件重置」这类流程，因为这是单机产品，没有可用的外发通道。

## 9. 队列只承载维护类任务

备份、恢复、日志轮转、凭据审计、存储自检。分析/生成/发表**没有**排进队列：分析需要人工在页面操作，发表不可重试。因此「关掉浏览器后继续跑一次分析」在 v0.1.0 不成立。

## 10. 审计日志未做防篡改

`logs/audit.jsonl` 是普通追加文件。能写数据目录的人可以改它。没有做签名链。

## 11. 备份不含凭据

这是刻意的，但意味着换机器恢复后必须重新填 API Key 与 Cookie。文档已说明。

## 12. 原插件的 234 个测试未全部迁移

只迁移了不依赖宿主核的部分（111 个断言）。`test/cordis-integration.test.ts` 之类测的是 DSH 集成，不再适用，已删除；其余与页面相关的测试由新的前端测试覆盖。

## 13. 页面文案仍有少量「插件」措辞

由于页面是从原插件逐字继承的，个别提示语里仍会出现「插件」「本部署」这类词。功能不受影响，措辞在后续版本统一。
