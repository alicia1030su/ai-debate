# 从 DSH 插件迁移

原来的 `dsh-ai-debate` 是 DSH 的插件，数据放在 DSH 的 profile 里。独立版**不会**自动读取那份数据，也不会修改或删除它。迁移只有一条路径：你在页面上主动点「导入」。

## 1. 先确认旧数据在哪

DSH 插件的默认位置是：

```
~/.dsh/ai-debate/state.json
```

如果你在插件里把「状态目录」（`storeDir`）改到了别处，去那里找。Windows 上 `~` 是 `C:\Users\<你>`。

## 2. 导入会做什么

在「系统」页点「导入 DSH 数据」：

1. 程序先做一次 **dry run**，只统计不写入：`state.json` 里有多少会话、多少候选、多少发表台账、多少审批记录，以及旧配置文件里有哪些字段。
2. 你确认后，程序把 `state.json` 复制到新数据目录，并保留原文件。
3. 旧配置里的**非敏感**字段（人格、长度、模型 Base URL、模型名等）会映射到新配置。旧配置里的 `tiebaCookie` / `llmApiKey` 是明文遗留字段，导入时**丢弃**；请在新页面凭据栏重新填一次。
4. 旧凭据（如果存在）不会被读取。程序没有解密旧宿主凭据存储的能力，也不会尝试。

如果新数据目录里已经有非空台账，导入会被拒绝（409），避免两份记录混在一起。这种情况下先备份，再手动决定保留哪一份。

## 3. 迁移后要重新做的事

| 项 | 为什么 |
|----|--------|
| 管理员账号 | 独立版有自己的登录体系，旧 DSH 会话不适用 |
| 模型 API Key / 平台 Cookie | 旧值在旧宿主的凭据存储里，或已作为明文配置丢弃 |
| 平台登录检查 | 在「平台」页重新点「检查登录」 |
| 发表能力验证 | 旧记录里的验证结果与账号绑定，独立版会重新判定；未验证的能力仍显示为不可用 |

## 4. 没有自动迁移的原因

- 旧目录可能被另一个仍在运行的 DSH 实例使用，自动读会与它竞争。
- 两份台账合并没有安全的默认规则：重复的发表记录一旦合并错误，会让「防重复发表」失效。
- 明文密钥不应该因为一次升级就被复制到第二个位置。

所以「不自动、要确认、不删原件」是刻意的。

## 5. 回滚

导入只做复制，不改原文件。要回到插件版：继续用原来的 DSH 插件与它原来的数据目录即可。独立版的数据在 `%LOCALAPPDATA%\ai-debate`（Windows）或 `~/.local/share/ai-debate`（Linux），删除它不影响旧插件。
