# 安全模型

这份文档说清楚 v0.1.0 保护什么、不保护什么，以及为什么。它不是营销材料：每一条「不防」都写明了前提。

## 1. 边界

独立版接管了原插件交给宿主的所有安全职责，同时新增了远程访问面。三条原则：

1. **默认不暴露**：默认只监听 `127.0.0.1`，管理接口没有任何「来自内网所以放行」的例外。
2. **失败时收口（fail-closed）**：认证中间件、审批闸门、去重台账在任何不确定状态下都拒绝执行，而不是放行。
3. **凭据只进不出**：API Key 与平台 Cookie 加密落盘，任何时候都不回显明文、不写日志、不以明文进入备份、不返回给浏览器。v0.2.2 起备份包含 `credentials.json` 密文，但不包含 `credentials.key`；跨机恢复会跳过无法解密的凭据并要求重填。

## 2. 认证

| 项 | 实现 |
|----|------|
| 首次初始化 | 仅在未初始化时开放；必须来自 loopback（或持有一开始打印的一次性 token），同源，`content-type: application/json`。成功后该接口永久关闭。 |
| 口令存储 | `scrypt`（N=16384, r=8, p=1，16 字节盐），`timingSafeEqual` 比对。口令至少 10 位，不得等于用户名。 |
| 会话 | 32 字节随机 id，Cookie `HttpOnly; SameSite=Strict; Path=/`，TLS 时追加 `Secure`；磁盘只存 `sha256`。空闲 12 小时、绝对 7 天过期。 |
| 登录限流 | 按 IP 与用户名双维度滑动窗口（15 分钟 8 次），超限 429 + `Retry-After`，并写入审计日志。 |
| CSRF | 非 GET 请求必须同源（`Origin` 与 `Host` 一致）+ `content-type: application/json`；`SameSite=Strict` 作为第二道。不依赖自定义头，因为页面本来就不发。 |
| 会话失效 | 改密、退出、`revokeAll` 后旧 Cookie 立即无效。 |

## 3. 凭据

- 算法：AES-256-GCM，随机 12 字节 IV，AAD 绑定凭据 ref 名（防止把 A 的密文塞进 B）。
- 密钥：首次保存凭据时生成 32 字节随机密钥，`credentials.key`，Linux `0600`，Windows 用 `icacls` 去掉继承并只授当前用户。仅启动或恢复不会创建新密钥，避免新机器恢复时因指纹不匹配而拒绝整份备份。
- 引用名白名单：只接受 `AI_DEBATE_*`，未知 ref 直接拒绝，防止核心将来加字段时写错命名空间。
- **不防**：同一台机器上同一用户的其他进程（它读得到密钥文件）。这不是本产品的威胁模型——那种攻击者已经能读你的浏览器 Cookie。要防它需要系统钥匙串，v0.1.0 没有做，理由见 `decisions.md`。

## 4. 发表

- 真实发表**永不**进入后台队列、**永不**自动重试。它必须由登录用户在对候选点「批准」后同步执行。
- 批准记录单次有效：同一条批准不能用来发第二条。
- 去重台账先写后发：先落盘「即将发表」，再发；写失败则拒绝发送（宁可少发，不可重发）。
- 未完成真机验证的平台能力保持 `unavailable`，界面上不会出现可点的发表按钮。
- 断网、鉴权失败、目标不匹配、内容被安全规则拦下时一律失败关闭，不降级、不猜测。

## 5. 输入与提示词

- 导入的讨论文本一律视为不可信输入，走既有的注入检测与输出守卫。
- 目标识别、身份归因、立场继承三条规则不接受「模型说是就是」。
- 模型输出在展示前做凭据泄漏扫描（包括 `AI_DEBATE_*` ref 名、Bearer token、Cookie 形态）。
- 出网守卫支持 `open` / `manual` / `offline` 三档，默认 `open` 但所有出网都记审计。

## 6. 远程访问

v0.1.0 支持把监听地址改成 `0.0.0.0` 或指定网卡，但**不内置 TLS 终止**。远程访问的正确做法：

0. `--host 0.0.0.0` 只改变监听范围，不改变信任范围。浏览器实际使用的域名必须写进 `AI_DEBATE_TRUSTED_HOSTS`（逗号分隔），否则管理接口会以 `403 forbidden: origin` 拒绝。默认只信任回环名——这是刻意的，不从 `Host` 头推断。

1. 用 Nginx/Caddy 反代到 `127.0.0.1:17860`，由反代提供 TLS。
2. 反代必须转发 `Host` 与 `Origin` 原样，否则同源校验会拒绝（这是设计意图）。
3. 不要把 17860 直接暴露到公网。
4. 首次初始化务必在本机完成，或在反代之后、仅允许自己的 IP 访问时完成。

如果必须直接监听公网地址而没有反代，请明确接受「口令在明文 HTTP 上传输」的风险——程序不会替你假装它是安全的。

## 7. 安装与升级

- 普通运行不需要 root/管理员：数据目录在用户目录内，端口 >1024。
- Linux 安装脚本需要 root（写 `/opt` 与 systemd 单元），但运行用户是 `ai-debate`，且 unit 限制了可写路径。
- 升级只替换二进制与 unit；`/var/lib/ai-debate` 与 `/etc/ai-debate/ai-debate.env` 保留。
- 卸载默认保留数据，删数据必须显式 `--purge --confirm-purge`。
- 备份包含七类白名单文件：`config.json`、`state.json`、`jobs.json`、`monitors.json`、`auto-tasks.json`、`reply-identities.json`、`credentials.json`。不含 `admin.json`、`credentials.key`、`sessions.json`、`run/`、`logs/`。因此备份仍应按敏感数据保管：凭据是密文，但密钥泄漏与备份泄漏同时发生即可解密。同机且密钥指纹匹配时恢复密文；新机器无密钥时跳过凭据并提示重填；密钥指纹不匹配时拒绝整个恢复。

## 8. 旧数据

原 DSH 插件的数据目录（`~/.dsh/ai-debate`）默认**不读、不改、不删**。只有用户在「系统」页主动触发导入，程序才会读取一次并复制到新目录；导入前先统计、再确认，目标台账非空时拒绝覆盖。

## 8.5 后台监控（v0.2.0，v0.2.1 扩展）

- 监控只能指向已注册平台的帖子链接：新建时先做 URL 解析，内网地址、`file://`、未知域名一律 400 且不落库。这是 SSRF 的入口围栏。
- 后台任务接口与会话同级鉴权；本机控制令牌**不**覆盖它，CLI 无法启停监控。
- 任务日志只记录 post id、会话 id 与错误文本，不记录回复正文以外的私有内容，也不记录凭据。
- 发表能力没有进入后台接口。候选终态是「待审核」，发布仍需审批页的一次性批准，且批准绑定正文哈希。
- 审计事件：`monitor.created` / `monitor.updated` / `monitor.removed` / `monitor.toggled` / `monitor.scanned` / `automation.paused` / `automation.resumed` / `queue.recovered` / `queue.pruned` / `queue.reaped` / `queue.retried` / `store.corrupt` / `store.restored` / `store.migrated`。
- **v0.2.1**：补偿扫描与全量重查同样只能对已解析的平台链接发起，走同一个 `probe` 入口；任务台账的清理**永不删除待审核任务**，避免候选失去来源；写入失败会进入降级并停止领取新任务，不会「带着坏台账继续跑」；模型调用在发出前落盘，中断后标记「结果不确定」，重试因此是可审计的。
