# AI Debate v0.2.0

从「需要人点一下」的工具，升级为「可以长期挂着」的后台 Agent。

## 新能力

**自动挂机页**（顶栏「自动挂机」，与原有 11 个配置页签并列，配置页签一个没动）

- 添加监控目标：填帖子链接，选择轮询间隔（≥120 秒），后台按间隔读取。
- 首次检查只建立基线，不分析历史回复——避免为一个 200 楼的旧帖付 200 次模型费。
- 之后每发现一条新回复，自动：分析上下文 → 继承主人立场 → 生成候选 → 过安全检查 → 放进待审核列表。
- 全局暂停/恢复、单目标暂停/恢复、立即检查、删除。
- 页面上的每个数字都来自服务端台账：今日发现、待审核、今日失败、队列长度、每个目标的最近检查/成功/错误。

**后台任务台账**

- 8 个状态：`pending / running / completed / retry_wait / needs_review / blocked / failed / cancelled`。
- 持久化，重启后恢复；中断的任务重新排队并记录原因。
- 去重：一个目标同时只跑一个探测；一条回复只产生一个候选（跨重启成立）。
- 限流按平台给出的 `Retry-After` 等待；认证失效直接暂停该监控并写明原因，不无限重试。
- 全局并发 1（可配 1–4），每平台 1；平台占满时任务释放回队列，不消耗重试次数。

**常驻**

- Windows：启动器改成 `supervise` 守护模式，服务异常退出后按 1s→30s 退避自动拉起；`stop` 是干净退出，守护不会对抗。
- Linux：systemd `Restart=always`，本次在**真实 systemd** 上做了安装/启停/kill -9 拉起/卸载保留数据/重装保留数据的完整验收。

## 安全边界（一条都没放宽）

- **仍然不能自动发表**：后台接口没有 publish；`/automation/publish` 与 `/automation/approve` 返回 404，并有测试钉住。
- 候选停在「待审核」，仍需在审批页生成一次性批准记录后才能手动发表。
- 新建监控前必须通过平台 URL 解析，非法链接（含内网地址、`file://`、未知域名）400 且不落库。
- 监控相关操作全部写审计日志；凭据路径没有任何新增。

## 升级

覆盖程序即可。新增 `monitors.json` 与 `auto-tasks.json` 两个文件，旧数据不受影响；不添加监控就完全等同于 v0.1.3 的行为。
