# 与原插件的差异清单

对照基线：`dsh-ai-debate` v0.3.0（DSH 插件）。本文件记录**独立版 v0.1.3** 与原插件的行为差异。保留的部分不逐条列出；下面每一条都是有意为之。

## 一、运行形态

| 项 | 原插件 | 独立版 |
|----|--------|--------|
| 安装 | 装进 DSH，由宿主加载 | Windows 单文件 EXE / Linux TGZ + systemd |
| 前置依赖 | DSH + Node.js | 无（Node 运行时打包在程序内） |
| 启动方式 | DSH 启动时挂载 | 双击 EXE / `systemctl start ai-debate` |
| 生命周期 | 跟随 DSH 进程 | 独立后台进程，关浏览器不停 |
| 端口 | 宿主 Web 端口 | 默认 `127.0.0.1:17860`，可改 |
| 多实例 | 一个 DSH profile 一个 | 一个数据目录一个进程（`run/server.json` 防重复） |

## 二、身份与安全

| 项 | 原插件 | 独立版 |
|----|--------|--------|
| 登录 | 复用 DSH 会话 Cookie | 独立管理员账号（scrypt）+ 会话（32 字节，磁盘只存 sha256） |
| 首次初始化 | 无（DSH 已登录） | 页面创建管理员；仅限本机或一次性令牌 |
| 登录限流 | 由宿主负责 | 按 IP 与用户名双维度，15 分钟 8 次 |
| CSRF | 宿主 `connection.requestRejection` | 同源校验 + `application/json` + `SameSite=Strict` |
| 凭据存储 | 宿主 credentials 服务 | 本机 AES-256-GCM + 独立密钥文件（0600） |
| 凭据引用名 | `DSH_AI_DEBATE_*` | `AI_DEBATE_*`（旧名仅在显式导入时识别） |
| 状态目录 | `~/.dsh/ai-debate` 或 `DSH_HOME` | `%LOCALAPPDATA%\ai-debate`、`$XDG_DATA_HOME/ai-debate`、`~/.local/share/ai-debate` |
| 管理接口默认监听 | 宿主 Web 地址 | 仅 `127.0.0.1`；改 `0.0.0.0` 需自行加 TLS 反代 |

## 三、模型

| 项 | 原插件 | 独立版 |
|----|--------|--------|
| 模型来源 | 「自动 / 宿主 / 自定义」三选 | 「自动 / 自定义」；没有宿主可借，`auto` 落到自定义的 OpenAI 兼容接口 |
| Base URL / Key / 模型 / 温度 / tokens / 超时 / 上下文 | 插件设置页 | 同样字段，同样页面 |
| 协议 | `chat/completions` 与 `responses` | 不变 |
| 出网守卫 | `open / manual / offline` | 不变（审计仍写 `egress.jsonl`） |

## 四、界面

| 项 | 原插件 | 独立版 |
|----|--------|--------|
| 载体 | DSH 设置面板的插件槽位 | 独立页面 `/` |
| 页签 | 11 个（`account`…`status`） | **同样 11 个，顺序不变**。需求文档写的是 10 个，实际源码是 11 个，这里以源码为准 |
| 页面代码 | `client/client.cjs`（7101 行） | 同一份代码经确定性脚本抽取（18 条带次数校验的替换），组件与交互保留；仅有「DSH 版本 / 宿主模型」等 11 处文案改为描述本服务 |
| 模块加载 | `window.__ModuleLoader__` | 自有加载壳（同名字符串仅作为遗留代码的调用点被替换） |
| 状态存储 | `@deepseek-ai/dsh-client-store` | 自实现 `createSnapshotStore`（`getSnapshot/subscribe/set`，通知不带参数） |
| 样式变量 | DSH 设计令牌 `--dsw-alias-*` | 同名令牌在 `theme.css` 里重新定义（浅色 + 深色） |
| 「DSH 版本」字段 | 显示宿主版本 | 显示本服务版本（`appVersion`） |
| 新增 | — | 顶栏：服务状态、系统页、退出登录 |
| 新增 | — | `/system` 只读状态页（版本、PID、端口、数据目录、队列、日志、旧数据提示） |

## 五、能力与流程

| 项 | 原插件 | 独立版 |
|----|--------|--------|
| 讨论导入 / 评论链 / 立场分析 / 人格 / 生成 / 安全评估 / 人工批准 / 复制 | 有 | 有，代码同一份 |
| 平台适配器与能力诊断 | 有 | 有；未验证能力仍显示不可用 |
| Agent 工具（9 个） | 注册到宿主，由 agent 调用 | 仍在内存中注册但**没有调用入口**（保留以便将来接 MCP）；不影响页面工作流 |
| 后台任务队列 | 无 | 有：备份 / 恢复 / 日志轮转 / 凭据审计 / 存储自检；重试+退避+暂停+崩溃恢复 |
| 发表进队列 | — | **永不**。发表保持同步、人工在场、一次性批准 |
| 备份 / 恢复 | 手动 | 页面与 CLI 均可，含凭据密文；不含密钥、口令哈希与会话 |
| 旧数据导入 | — | 仅手动触发，先扫描再确认，不覆盖非空台账 |

## 六、测试与构建

| 项 | 原插件 | 独立版 |
|----|--------|--------|
| 测试 | 234 个文件 | 核心 113 + 服务端 20 + 前端 6 + 端到端 25 项 |
| 构建产物 | npm 包 + TGZ 源码包 | Windows EXE + Linux TGZ（各带 SHA256） |
| 运行时检查 | 依赖宿主 | `scripts/assert-no-dsh.mjs`：源码、清单、线路、二进制四层检查 |

## 七、明确不做的事

- 不读取、不修改、不删除原插件的 `~/.dsh/ai-debate`。
- 不把 DSH 的登录态、凭据或 profile 直接搬过来。
- 不为了「看起来独立」而重写辩论引擎——业务逻辑一行未改。
