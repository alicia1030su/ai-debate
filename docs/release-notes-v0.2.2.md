# AI Debate v0.2.2

更稳定的后台挂机、可恢复的备份中心，以及更容易定位问题的运行诊断。

> **发布状态说明**：最终冻结候选回归已通过，B1–B4 与 Soak/持久化架构复审 **IS_PASS YES**；全新连续 24h Soak 正在运行。v0.2.2 CI、最终 Windows EXE/Linux TGZ 与正式 Release/Tag/Latest 尚未完成，当前判定为 **NO-GO**。文末“发布前验收状态”必须在正式打 Tag 前回填，不能把架构放行当作正式发布签字。

## 升级

覆盖程序即可，**不需要手工修改数据文件**：

- Windows：用新 EXE 覆盖旧程序；默认数据目录仍是 `%LOCALAPPDATA%\ai-debate`。
- Linux：用新包中的 `install.sh` 覆盖升级；默认保留 `/var/lib/ai-debate` 与 `/etc/ai-debate/ai-debate.env`。
- 管理员账号、模型配置、平台凭据、监控、待审核候选与核心台账继续使用原目录。
- 旧监控字段会按默认值补齐并写回；已有候选、批准和终态任务不会被改写。
- 同机升级保留 `credentials.key`，原有加密凭据可继续解密。

升级前仍建议先停服务，再完整复制整个数据目录。不要只复制 `state.json`：管理员、密钥、监控、任务、会话和备份都属于同一份状态。

### 自动身份迁移

v0.2.2 新增全局回复身份台账 `reply-identities.json`，用于防止同一回复被多个监控重复分析。升级时会在后台引擎启动前，从旧监控 `seen`、游标指纹、任务与核心候选自动重建身份：

- 身份文件不存在时原子创建；已存在时不覆盖新证据；
- 旧任务缺 `identityKey/identityKeys` 时可幂等回填；
- 身份或监控源台账不可读时，服务与健康检查仍可用，但自动化与核心/手工分析接口熔断，避免以空身份栅栏重放旧回复；
- `state.json` 损坏、监控/会话上下文冲突、非法候选或多个已批准候选冲突时迁移熔断，不写半成品；
- 真实 v0.2.1 升级验收 **97/97 通过，`identityMigration: "migrated"`，`modelCalls=0`**；迁移相关测试合计 **38/38**。

## 新功能与改进

### 自动挂机页

顶栏新增独立的“自动挂机”入口，把运行状态与操作集中在一页：

- 添加、暂停、恢复、删除监控；
- 立即检查、只读平台检查、补偿扫描、全量重查；
- 调整补偿回看窗口；
- 查看调度心跳、队列、内存、磁盘、扫描覆盖与错误；
- 重试失败任务、取消等待任务、清理历史；
- 查看待人工审核候选；
- 直接创建、校验、恢复备份；
- 导出不含秘密的诊断报告。

页面只显示服务端真实返回值；未知数值显示“—”，不会用“0”冒充未知。

### 同一回复只处理一次

新增全局 `stable/fallback` 回复身份：

- 贴吧等能提供持久回复 ID 的平台使用稳定身份；
- 其他平台使用内容指纹回退，并明确标注其限制；
- 身份跨监控、跨分析会话、跨重启生效；
- 即使身份已保存而分析任务尚未写入，orphan sweep 也会把遗漏任务补回。

### 任务租约与崩溃恢复

后台任务现在持久化租约与心跳。进程退出后：

- 不再遗留“永远执行中”的任务；
- 中断任务恢复排队并清除旧租约；
- 期间可能发出的模型调用标记为“结果不确定”；
- 重试前先检查是否已有候选，避免重复生成记录。

模型请求本身仍可能重复，产品不承诺 exactly-once；但重复与不确定状态现在可见、可审计。

### 游标与贴吧读取

- 不完整扫描不再声称“已完整覆盖”；
- 已看到的回复仍会记录，避免重复入队；
- 编辑只记录变化，不重新生成候选；
- 只有全量重查才判定删除；
- 补偿扫描发现真正的新回复时仍会分析；
- 贴吧分页增加错页、空页、截断与 `pagingState` 诊断；
- 429 遵循 `Retry-After`，401/403/验证码暂停监控；
- 楼中楼分页被限流时冷却并改用内联数据，同时说明覆盖不足。

### 备份中心

备份固定包含七类文件：

```text
config.json、state.json、jobs.json、monitors.json、
auto-tasks.json、reply-identities.json、credentials.json
```

不包含密钥、管理员、会话、运行记录或日志。

- 每份备份都有 SHA-256 清单，可逐文件校验；
- 每日备份保留 7 份、每周保留 4 份；
- 手动与恢复前备份不会自动删除；
- 恢复前自动创建 `pre-restore-*` 快照；
- 恢复前检查磁盘空间与凭据密钥指纹；
- 恢复失败会尝试回滚，并明确报告回滚是否完整；失败后自动恢复队列运行并重启后台引擎；
- 恢复成功后会受控重启以重新加载台账，终态与日志通过独立 receipt 保留；
- receipt 损坏或超过大小/数量上限时安全降级，不影响管理页诊断。

### 安全与部署

- HTTPS 反代可显式开启 Secure Cookie：`--secure-cookies` 或 `AI_DEBATE_SECURE_COOKIES=1`；
- 备份、诊断与自动挂机接口需要登录会话，本机 control token 不能越权访问；
- 诊断导出不包含 Cookie、密钥、会话或 control token；
- 平台 HTTP 使用 manual 逐跳重定向，每跳重新执行出网策略并跨域剥离凭据、隔离 Cookie；全模式私网/回环/link-local/metadata 拒绝已通过 Core 227/227；DNS 固定已修复：首次 socket lookup 固定 A/AAAA 并复用，生产 fetch 使用 dispatcher 时同源重定向不重复解析，新 host 逐跳校验，策略变严仍复验；
- Linux systemd 正确区分正常停止与受控重启；
- Linux 安装/卸载增加路径白名单、符号链接与元字符检查；
- 增加 logrotate 配置；
- 卸载默认保留数据，彻底删除必须 `--purge --confirm-purge`。

## 没有变的部分

- **后台仍然不能自动发表。** 后台只做读取、分析和候选生成，候选停在“待人工审核”；发表必须由人在审批页确认。
- 发表不进入后台队列，也不会自动重试。
- 11 个配置/工作流页签与人工审批流程保持不变。
- 默认仍只监听 `127.0.0.1`；远程访问必须显式配置可信域名并使用 TLS 反代。

## 备份保密提示

v0.2.2 的备份包含 `credentials.json` **密文**，但不是“可以公开分享的文件”。如果备份与原 `credentials.key` 同时泄漏，凭据就可以被解密。

- 同机且密钥指纹匹配：恢复密文；
- 新机器没有密钥：跳过凭据，恢复其他数据，要求重新填写；
- 新机器已有不同密钥：拒绝整个恢复，避免写入不可用密文。

需要跨机器带走凭据时，请使用受控的秘密传递方式，并单独保管密钥；不要把密钥和备份放进同一个公开附件或聊天群。

## 已知限制

- 真实贴吧/微博账号的长期轮询与真实发表尚未验证。
- 全模式私网/回环/link-local/metadata 拒绝与 DNS rebinding socket 级固定已通过 Core 227/227；`isPinned` 仅在成功策略校验的 socket lookup 后为 true，忽略 dispatcher 的自定义/注入 fetch 不会触发真实 lookup，代理配置兼容与 CookieJar 属性模型仍是已知边界。
- Windows 注册表自启在本构建机上受主机策略限制，未验证。
- Debian 12 的 systemd 生命周期尚未在真实 init 环境验证。
- 秘密扫描默认整文件豁免 scanner 与 fixtures README，目录模式会跳过 >4 MiB、深度>8、文件数>5000；SEA 二进制通过 `--baseline` 单独差分：PE 只放行 Node 运行时同偏移原字节；ELF 按节名和大小配对，要求至少 99% 可加载代码/静态数据字节一致；只放行对应字节也完全相同的运行时原匹配，新增 note、改写或未匹配字节仍拦截。
- 备份中的手动/恢复前副本不会自动清理，长期运行需关注磁盘空间。
- 日志轮转使用 `copytruncate`，极短的截断/写入窗口可能丢失少量日志。
- Windows EXE 未代码签名，首次运行可能出现 SmartScreen 提示。

正式 Release 发布后，附件应包含 `SHA256SUMS.txt`：

```bash
sha256sum -c SHA256SUMS.txt
```

```powershell
certutil -hashfile AI-Debate-windows-x64.exe SHA256
```

核对 Release 页面公布的 SHA256 后再运行。未签名的 EXE 出现“未知发布者”提示时，不要仅因为提示而放行；先确认下载来源与哈希。
